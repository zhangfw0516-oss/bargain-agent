总路线：[DEVELOPMENT_PLAN.md](../../DEVELOPMENT_PLAN.md)。

**当前执行：[阶段 01：接口确认与真实基础闭环](01-foundation.md)。**

本目录将总路线拆成实际执行批次。阶段 01 对应总计划阶段 0 的收尾及阶段 1；批次编号不等于总路线编号。

## 文档怎么分

| 文档 | 用途 | 更新规则 |
| --- | --- | --- |
| 总计划 | 长期目标、依赖、固定职责 | 复盘后按证据调整，不提前宣布完成 |
| 当前阶段子文档 | 本阶段谁做什么、交付什么、怎样验收 | 成员有新成果或阻塞时更新状态和证据 |
| 阶段总结 | 本阶段实际完成、未完成、问题和调整理由 | 收尾时填写；保留历史，不覆盖成下一阶段 |
| 下一阶段子文档 | 根据上一阶段总结形成的新任务 | 复盘后创建；不预先填成既定任务 |

## 滚动更新流程

1. 成员提交任务编号、分支/PR、运行步骤、测试结果及阻塞。
2. Lead 核对证据，更新当前子文档。开发中、待评审、已验收必须区分。
3. 阶段收尾时，用 [模板](TEMPLATE.md) 的总结部分写清实际结果。
4. 根据结果调整总计划：保留、拆分、延期或取消任务均说明理由。提案承诺的删减需要与导师确认。
5. 用同一模板创建下一阶段文件，说明继承的未完成任务、依赖和每人职责。
6. 更新本入口的“当前执行”链接及阶段索引。

“实时调整”指收到新证据后及时修订，不代表已配置后台监控。没有新的提交或测试证据时，状态保持待核对；不能假定成员完成。以后请求“更新阶段进度”或提供成果时，按此流程核对和更新。

## 状态与责任规则

- 未开始：尚无开发证据；待核对：可能已有成果但未核验。
- 进行中：正在开发；待评审：已提交成果和验证方法。
- 已验收：评审人确认验收条件满足，并记录证据。
- 阻塞：写明原因、协助人和可继续的独立工作。
- 只有已验收任务勾选完成。代码行数、时间和上传行为都不能单独证明完成。
- Lead 负责协调、接口和集成，不自动接管成员的模块开发。AI 生成的候选代码需由模块负责人评审，贡献按实际工作记录。
