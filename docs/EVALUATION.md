## 1. 口径声明（先读这一节）

本评估跑的是**本地确定性代码 + 注入的假抓取/假发送**，全程离线。因此：

1. **不代表真实 LLM 解析准确率。** 指令解析类结果来自本地 schema 校验器与离线演示词法解析器。
2. **不代表真实站点价格抽取准确率。** 报价抽取只用了 4 个既有离线 fixture 与合成的 JSON-LD/OpenGraph 页面。
3. **不代表真实通知投递。** 通知类结果用注入的假发送函数计数，**零 SMTP 拨号**。
4. **期望标签是评估者按项目既有规则手工标注的**，属**一致性/回归符合性**检查，不是独立第三方基准。
   因此“通过率高”只能说明规则按文档执行，不能证明真实世界泛化能力。
5. 没有任何新的 Brave / DeepSeek / 商家网页 / SMTP 调用；未读取或修改 `.env` 与凭据；
   未改动任何生产模块或阶段 D 文件。

## 2. 复跑方式（一条命令）

在仓库根目录：

```bash
./venv/Scripts/python.exe -m evaluation            # 打印人读摘要，退出码 0 表示全部通过
./venv/Scripts/python.exe -m evaluation --json eval_report.json   # 另存机器可读结果
```

针对性离线回归（不跑全套）：

```bash
./venv/Scripts/python.exe -m unittest tests.test_evaluation -v
```

| 位置 | 内容 |

## 4. 四个评估项：输入 / 预期 / 实际 / 计数 / 失败样本

所有计数来自 `python -m evaluation` 的本次运行。

### 4.1 本地指令 schema 校验（`instruction_schema`）

- **被测对象**：`schemas.validate_search_request`（schema v2 搜索请求）与
  `schemas.validate_task`（schema v1 监控任务）。衡量**本地校验守卫**，不是 LLM。
- **输入**：23 条手写“已解析字典 + 原始指令”，覆盖：中英文完整请求、缺预算、有预算缺币种、
  模型编造颜色/容量、非法币种、负预算、三位小数、频率越界/布尔、URL 未由用户提供、
  多余字段、非法状态、unsupported 无解释、字段过长，以及 v1 任务的缺失价/类型错/非法比较符。
- **预期**：合法者被接受并归一化（如预算 `"200.00"`），非法者抛 `ValueError` 拒绝。
- **实际**：**23/23 符合预期**（含 v1 任务 4 条）。
- **计数/指标**（分母为 23）：

  | 指标 | 值 |
  | --- | --- |
  | 用例数 | 23 |
  | 正确 | 23 |
  | 准确率 | 1.00 |
  | 预期接受 / 预期拒绝 | 8 / 15 |
  | **危险误接收（应拒绝却接受）** | **0** |
  | 误拒绝（应接受却拒绝） | 0 |
  | 接受召回 / 拒绝召回 | 1.00 / 1.00 |

- **失败样本**：本次为 0。开发过程中曾发现 1 处**用例自身构造错误**（在 unsupported 请求上仍带
  了 `colour="black"`，触发防编造校验），已修正用例而非改动产品代码。

### 4.2 商品同款 / 错款 / 存疑判定（`identity`）

- **被测对象**：确定性身份匹配三处入口——搜索卡片级 `discovery.match_candidate`、
  详情页级 `discovery._detail_identity`、监控级 `scheduler.quote_identity_verdict`。
- **输入**：30 条用例，三态标签 `same` / `different` / `needs_confirmation`，覆盖：
  真实 Fitbit Air 的 Obsidian/Lavender/Berry、Inspire 3、Charge 6、配件（band/cable）、
  Sony WH-1000XM5 的“名称省略品牌由结构化 brand 补足”与“名称 Bose vs brand Sony 自相矛盾”、
  化妆品容量 30ml/60ml、条件（new/used）冲突与未声明、以及合成的 AeroBuds 全谱。
- **预期/实际**：**30/30 一致**；层级分布 候选 15 / 详情 7 / 监控 8。
- **计数/指标**（分母为 30；`same` 为正类）：

  | 指标 | 值 |
  | --- | --- |
  | 用例数 | 30 |
  | 正确 / 准确率 | 30 / 1.00 |
  | 预期 `same` 数 | 7 |
  | `same` 真阳性 / 假阳性 / 假阴性 | 7 / 0 / 0 |
  | **`same` precision** | **1.00** |
  | **`same` recall** | **1.00** |
  | **错款误接收数（应 `different` 却判 `same`）** | **0** |
  | 存疑误接收数（应 `needs_confirmation` 却判 `same`） | 0 |

- **失败样本**：本次为 0。因“错款误接收”是安全侧最危险错误，指标中单独列出，并保持为 0。

### 4.3 静态商品页面报价抽取（`quote_extraction`）

- **被测对象**：`scraper._parse_page`（`fetch_quote` 的静态解析核心）。
- **输入**：16 个页面——4 个既有 fixture（Kindle 319.00 / Galaxy A17 433.00 / K1 MAX 1399.00 /
  iPhone 16 Pro 2999.00 缺货）与 12 个合成页（JSON-LD 数组、品牌对象、`1,299.00` 千分位、
  未知库存、预购、重复 Offer、OpenGraph 回退，以及必须拒绝的：多商品歧义、缺价、缺币种、
  Offer 冲突、空页）。
- **核对方式**：**金额、币种、库存三项必须同时对**才计为通过；必须拒绝的用例以“是否抛
  `ScraperError`”为通过。
- **实际**：**16/16 符合预期**（11 条抽取 + 5 条拒绝）。
- **计数/指标**：

  | 指标 | 值 | 分母 |
  | --- | --- | --- |
  | 用例数 | 16 | — |
  | 可抽取用例 | 11 | — |
  | 三项全对（金额+币种+库存） | 11 | 11 |
  | 金额正确 | 11 | 11 |
  | 币种正确 | 11 | 11 |
  | 库存正确 | 11 | 11 |
  | 应拒绝且正确拒绝 | 5 | 5 |
  | 总体准确率 | 1.00 | 16 |

- **失败样本**：本次为 0。歧义/缺价/缺币种/冲突/空页均按要求**拒绝而非猜测**。

### 4.4 两来源优惠通知去重与失败隔离（`notification_dedup`）

- **被测对象**：`scheduler.check_task`（多来源聚合检查），注入假抓取与假发送，临时 SQLite。
- **输入**：9 个场景，每个建一个两来源任务（已确认身份 Fitbit Air/黑）：
  两源同时达标、两源同价、单源失败另一源达标、失败不结束优惠区间、缺货不选为最优、
  两源回到阈值上重置、配件页（NZD 19）不得成为最优、可重试发送失败后重发、永久发送失败。
- **预期/实际**：**9/9 符合预期**。
- **计数/指标**：

  | 指标 | 值 | 分母 |
  | --- | --- | --- |
  | 场景数 | 9 | — |
  | 正确 | 9 | 9 |
  | 去重场景（每个场景都核对发送次数） | 9 | 9 |
  | 失败隔离场景（显式 `failure_isolation` 标签） | 4 | 4 |
  | 假发送调用合计 | 10（含 1 次可重试失败后的重发） | — |

  分母来源说明：`instruction_schema` 的 23、`identity` 的 30、`quote_extraction` 的 11/5
  均来自固定用例集的分组；`notification_dedup` 的失败隔离分母**不**从用例 `expected` 里
  偶然出现的键推断，而是由数据集上显式的 `failure_isolation` 标签决定——只有真正注入
  来源失败或发送失败的 4 个场景（单源失败仍发 1 封、失败不结束优惠区间、可重试发送失败后
  重发、永久发送失败记录一次）计入，故分子/分母语义独立于断言键。

  关键断言：两源都达标 **只发 1 封**；第二次相同检查**不重发**；单源失败时另一源仍被检查且
  照常发 1 封；失败**不**被当作“优惠结束”（不重置、不重发）；缺货源不会被选为最优；
  配件页不会成为优惠；可重试失败在下一次检查重发一次后成功；永久失败记录一次且不崩溃。

- **失败样本**：本次为 0。

## 7. 采样偏差与商家覆盖边界（必须随结论一起呈现）

**采样偏差**

- 商品高度集中在少数用例：Fitbit Air、Sony WH-1000XM5、The Ordinary 系列、Kindle/Samsung/iPhone，
  以及纯构造的 AeroBuds。**不能**外推到“所有电子产品/化妆品”。
- 身份用例的期望标签由项目作者按既有规则手工标注，规则又由同一批人实现并测试，存在**循环性**；
  高通过率是“代码符合文档规则”，不是独立基准准确率。
- 合成 HTML 命名规范、字段齐全，**低估**真实网页的噪声（缺失字段、动态渲染、多 Offer 冲突、
  反爬页面）；真实网页抓价失败率（如 §18 的 403/无 JSON-LD）远高于本离线集。
- 报价只覆盖 NZD（以及少量 USD/AUD 币种不符），**同币种比较**，无汇率换算。

**商家覆盖边界**

- 真实可用商家仅 **PB Tech + JB Hi-Fi NZ** 两家；**Mighty Ape** 整站 403 未验证；
  Brave 网页候选依赖密钥与使用权，且覆盖不稳定。
- 因此任何比价结论只在“已配置且可访问的商家范围 + 查询时间 + 库存状态”内成立，
  **不代表全网最低价**；运费不在报价内（页面多未提供）。
- 本次所有结果均为**离线**，商家覆盖边界与真实评估无关，仅用于说明离线集不覆盖真实商家多样性。

## 9. 局限与下一步（建议）

- 本离线集是**回归护栏**：任何改动破坏规则时，`python -m unittest tests.test_evaluation` 会失败。
- 扩充方向（需另行授权真实调用，且应保留调用次数与授权边界记录）：
  1. 用**人工核对**的真实商品页批量核验金额/币种/库存，按商家分别给出 precision/recall 与分母；
  2. 扩大真实解析样本并**冻结**为非确定性用例，报告 pass@1 与 fail-closed 率，不美化中文颜色案例；
  3. 授权后做一次真实多来源收信与一段有限时的持续监控，报告真实通知 TP/漏报/误报；
  4. 若取得 Brave 结果持久化许可，再评估广域发现覆盖与抓价成功率。
- 在以上完成前，课程报告应把第 4 节标为“离线一致性评估”，把第 6 节标为“真实证据与缺口”，
  **不得**把第 4 节的 1.00 写成真实 LLM 或真实站点准确率。
